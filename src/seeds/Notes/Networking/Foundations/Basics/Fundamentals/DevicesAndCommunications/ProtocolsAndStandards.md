# How Protocols and Standards Let Devices Communicate

<hr class="dividerSection" />

### What Is a Protocol?

<hr class="dividerSection" />

A <span class="emphasis">protocol</span> is a set of rules defining how data should be communicated between devices over a network.

Protocols are the languages that computers use to communicate with each other.

<hr class="dividerSection" />

### The Proprietary Era

<hr class="dividerSection" />

Since the early days of computer networking, there have been several attempts to define the functions needed for computers to communicate with each other.

These early protocols were often developed by a specific vendor, such as IBM, to be used with their own products.

With this proprietary approach, enabling communication between different vendors' products was difficult.

For example, a device made by one vendor could send a request to a server made by a different vendor, but the request could fail simply because the two systems spoke different, incompatible protocols, not because of any physical connection problem.

<hr class="dividerSection" />

### What Is a Standard?

<hr class="dividerSection" />

A <span class="emphasis">standard</span> is an agreed-upon specification that describes how a protocol or technology should work.

With <span class="secondEmphasis">vendor-neutral</span> standards, devices of all types can communicate with each other, regardless of who manufactured them.

<hr class="dividerSection" />

### Standards in Practice

<hr class="dividerSection" />

Vendor-neutral standards are what make everyday cross-device communication possible.

Examples include:

<div class="centeredBullet">
  <ul class="diamondBullets fullWidthBullet">
    <li>An Apple MacBook can access a website hosted on a web server running Linux.</li>
    <li>A PC running Windows can send an email that can be read on a smartphone running Android.</li>
  </ul>
</div>

<hr class="dividerSection" />

### How Internet Standards Are Created (RFCs)

<hr class="dividerSection" />

An internet standard is the end result of a comprehensive cycle of <span class="emphasis">discussion, problem solving, and testing</span>.

When a new standard is proposed, each stage of the development and approval process is recorded in a numbered <span class="emphasis">Request for Comments (RFC)</span> document so that the evolution of the standard is tracked.

RFCs for internet standards are published and managed by the <span class="emphasis">Internet Engineering Task Force (IETF)</span>.

<hr class="dividerSection" />

### Common Standards Bodies (High-Level)

<hr class="dividerSection" />

Different organizations support standards across different parts of networking.

Examples include:

<div class="centeredBullet">
  <ul class="diamondBullets fullWidthBullet">
    <li><span class="emphasis">IETF</span>, publishes RFCs and standardizes many core internet protocols.</li>
    <li><span class="emphasis">IEEE</span>, defines many LAN/WLAN technical standards (ex: 802.3 Ethernet, 802.11 Wi-Fi).</li>
    <li><span class="emphasis">ICANN</span>, coordinates global domain names and IP-related resources.</li>
    <li><span class="emphasis">IANA</span>, manages core internet registries (IP allocations, protocol parameters, etc.).</li>
    <li><span class="emphasis">ITU</span>, develops global telecom standards (especially carrier and international telecom space).</li>
    <li><span class="emphasis">TIA</span>, defines many cabling and physical infrastructure standards (ex: wiring specs).</li>
  </ul>
</div>

These organizations are referenced again in specific sections throughout the notes (Ethernet, Wi-Fi, cabling, routing, etc.).
